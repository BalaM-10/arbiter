# Why QNX

Each QNX OS 8.0 feature Arbiter uses, the failure it handles in the tabletop
scenario, the fault scenario that proves it, and the saved log. A row without a
log is designed but not yet proven on QNX. Claims refer to
[`THREAT_MODEL.md`](THREAT_MODEL.md); code locations and 8.0 documentation pages
are in [`QNX_EVIDENCE.md`](QNX_EVIDENCE.md).

| QNX feature | Failure it handles | Proven by | Log |
| --- | --- | --- | --- |
| Synchronous message passing (`MsgSend`/`MsgReceive`/`MsgReply`) | A command is never acted on before its verdict, and a flooding sender is blocked by its own sends (TM-C1, TM-C3) | F3, F8 | Mechanism on QNX: `evidence/runs/2026-11-13-qemu/run-130755.log` (M0-MSG-1, -3, -4); F3, F8: not built yet (M2 P7) |
| Kernel-reported sender identity (`_msg_info`, `ConnectClientInfo()`) | A process that is not the guardian sends setpoints to the arm, or a process that is not the gateway submits commands to the guardian (TM-C2) | F11, policy off | F11, every case with the policy off: `f11_suite` in `evidence/runs/2026-11-16-qemu/run-202754.log` (lines 713-829); `fr_g10_only_the_gateway_user_may_submit` (line 652); `fr_g6_arm_rejects_setpoints_from_another_process` |
| Resource manager at `/dev/arbiter`, close handler | The gateway dies; the guardian learns at once instead of waiting for silence (TM-C4) | F10 | Mechanism on QNX: `fr_g5_last_client_close_enters_hold` and `fr_g5_submitter_killed_with_a_status_reader_open_holds_at_once` in `guardian_suite` (`evidence/runs/2026-11-16-qemu/run-202754.log`); F10 in the bench: not built yet (M2 P7) |
| Pulses | Heartbeats and lease renewals must never block the sender (TM-C4) | F13 | Mechanism on QNX: `run-130755.log` (M0-MSG-6); F13 in the bench: not built yet (M2 P7) |
| Strict fixed-priority FIFO scheduling, trusted threads in the privileged range | A flood, a pulse flood or a CPU hog at the gateway's priority delays the arm's control loop or the watchdog, or boosts the guardian above them (TM-C3) | F3, F12 | not built yet (M2 P7) |
| `_NTO_CHF_FIXED_PRIORITY` channels | The guardian would otherwise drop to its low-priority client's priority while serving it (TM-C3) | F12 | Mechanism on QNX: each trusted process still at its priority after client traffic (`nfr_i5_trusted_processes_keep_their_priority_after_dropping_privileges`, `evidence/runs/2026-11-16-qemu/run-202754.log` line 437); F12: not built yet (M2 P7) |
| Timer that delivers a pulse (`timer_create`) | The arm's 1 kHz loop and its motion lease run on the arm's own clock, independent of any other process (TM-C4) | F1, F13 | Mechanism on QNX: `arm_suite` (loop period, lease expiry with the guardian stopped) in `evidence/runs/2026-11-13-qemu/run-144326.log` |
| `TimerTimeout()` on the setpoint send | A hung arm controller would hang the guardian; instead the send times out and the guardian enters `SAFE_STOP` (TM-C4) | `fr_g9_arm_never_replies_times_out_and_safe_stops`, `fr_g9_arm_not_receiving_times_out_and_safe_stops` | `test_send_timeout` in `evidence/runs/2026-11-13-qemu/run-133305.log` (2 ms requested, 2 to 4 ms measured); guardian with a stand-in arm: `guardian_suite` (`evidence/runs/2026-11-13-qemu/run-141527.log`) |
| `_NTO_CHF_DISCONNECT` on the arm's channel | The guardian dies mid-move; the kernel tells the arm, which brakes at once (TM-C4) | F13 | Mechanism on QNX: `fr_a4_guardian_killed_arm_brakes` in `arm_suite` (`evidence/runs/2026-11-13-qemu/run-144326.log`); with the watchdog recording the cause: `fr_w3_watchdog_records_that_the_guardian_died` (`evidence/runs/2026-11-14-qemu/run-190222.log`); F13 in the bench: not built yet (M2 P7) |
| Process-manager death notices (`procmgr_event_notify_add`, `MsgRegisterEvent`) | A trusted process dies; the watchdog learns which one and records it (TM-C4) | F13 | Mechanism on QNX: `watchdog_suite` and `fr_w3_watchdog_records_that_the_guardian_died` (`evidence/runs/2026-11-13-qemu/run-150602.log`); F13 in the bench: not built yet (M2 P7) |
| `MsgDeliverEvent()` with registered events | The watchdog must tell the arm to brake without a message that could block it on a faulty process; a frozen watchdog must stop the system too (TM-C4) | F13, FR-W6 | Mechanism on QNX: `fr_w2_*` in `watchdog_suite` and `arm_suite` (`evidence/runs/2026-11-13-qemu/run-150602.log`); the watchdog's beat and the stopped-watchdog tests `fr_w6_*` (`evidence/runs/2026-11-16-qemu/run-202754.log`) |
| The connection a pulse came in on (`struct _pulse` `scoid`) | A process forges the arm's tick, the watchdog's beat or its trip, even with the right value (TM-C3, TM-C4) | `fr_a1_forged_tick_pulses_do_not_drive_the_loop`, `fr_w6_forged_beat_with_the_right_token_is_refused`, `fr_w2_forged_trip_with_the_right_token_is_refused` | `evidence/runs/2026-11-16-qemu/run-202754.log`: 2000 forged ticks ignored; 200 forged beats and trips with the right token per side refused (`test_wd_scoid`); before the connection check, `evidence/runs/2026-11-16-qemu/run-202341.log`: the forged beats hid a silent watchdog |
| Separate processes on a microkernel | A crash in the gateway or planner cannot corrupt the guardian, the arm or the watchdog (TM-C4) | F10 | not built yet: the gateway and planner are M2 P6, F10 is P7 |
| Security policy (`secpolcompile`, `secpolpush`, `on -T`) | An untrusted process connects to the arm at all; the kernel refuses it before any Arbiter code runs (TM-C2) | F11, policy on | QEMU policy image: `policy_suite` (rules read back from the kernel with `secpol`, `fr_s1`..`fr_s5`) and `f11_suite on` in `evidence/runs/2026-11-16-qemu_secpol/run-203526.log` |
| Abilities and privilege dropping (`procmgr_ability`) | A compromised trusted process keeps powers it never needed (NFR-I5) | `nfr_i5_dropped_abilities_are_denied` | `evidence/runs/2026-11-16-qemu/run-202754.log` line 438: each trusted process runs as its own user and checks at startup that `setuid(0)`, `fork()` and a higher priority are refused |
| Cycle counter (`ClockCycles()`) | Decision latency would be guessed instead of measured (NFR-T2) | Timing runs on the Pi 5 | not yet: hardware timing is M3 |
| Kernel trace (`tracelogger`) | The isolation claim would rest on assertion instead of a recording (NFR-Q5) | F3, F12 | not built yet (M2 P7) |

QEMU runs prove function only. Timing is reported only from Raspberry Pi 5 runs,
as measurements, never as guarantees.
