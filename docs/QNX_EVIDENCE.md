# QNX evidence map

Every QNX 8.0 feature this repository uses, why it is needed, where it is used,
the 8.0 documentation page, and the saved output that shows it running on QNX.

Status: milestone M2, in progress (2026-11-17). The guardian (`qnx/guardian/`),
the arm controller (`qnx/arm/`) and the watchdog (`qnx/watchdog/`) run on QNX,
alone and end to end, each as its own user, on two QEMU images (security policy
off and on); the fault bench (F1, F4, F5, F6, F9) runs against them
(`arbiter bench run`); the guardian's fault tests also use a stand-in arm
(`qnx/tests/arb_arm_stub.c`). Rows marked "sample" come from the M0
message-passing sample, a toolchain check that is not part of the guardian.
Why each feature matters in the scenario: `docs/WHY_QNX.md`.

Target for all proofs below: QEMU x86_64 image built with `mkqnximage`,
QNX SDP 8.0.4 (see `docs/TARGETS.md`). Requirement IDs in parentheses are
defined in `docs/REQUIREMENTS_SUMMARY.md`.

## Security policies

The policy is `qnx/image/policy/arbiter.secpol`, built into a second QEMU image
(`./scripts/build-image.sh qemu_secpol`, target `qemu_secpol`). The first image
(`qemu`) has no policy and runs every code-level check alone (FR-S6).
